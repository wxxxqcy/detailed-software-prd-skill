# MODE-F Lite 页面详细需求模板

用于 MODE-F Lite / STEP-3。

目标：把现有页面整理成测试和交付能直接使用的页面需求，不重新设计页面。

一次最多处理 5 个页面。

---

| 项目 | 内容 |

| 页面编号 | P-X-001 |
| 页面名称 |  |

---

## 2. 页面入口

记录真实入口：

```text
来源页面 / 菜单 / 路由
→ 触发元素
→ 当前页面
```

无法确认时写【待确认】。

---

## 3. 页面结构

只记录当前页面真实存在的主要区域：

1. ...
2. ...
3. ...

MODE-F Lite 默认不要求 ASCII。
只有用户明确要求，或没有视觉资料且结构难以文字表达时，才使用 ASCII。

---

## 6. 页面跳转

只写已验证跳转。

```text

```

未知跳转不猜。

---

## 7. 页面状态

只列真实存在或已确认需要测试的状态。

- Error
- Disabled
- 无权限

禁止机械补全所有候选状态。

## 9. 测试验收点

只覆盖页面核心行为。

正式 AC 只能建立在【现有实现】或【已确认需求】之上。

示例：

### AC-PX001-01
Given ...
When ...
Then ...

如果规则尚未确认，不写正式 AC，改为：

【待确认测试点】
- ...

---

# 页面完成前最小检查

1. 页面入口是否有依据
2. 页面主要区域是否漏掉
3. 每个关键按钮是否说明点击结果
4. 跳转是否与真实系统一致
5. 页面状态是否来自真实实现或明确需求
6. 权限是否有依据
7. 是否把“行业通常如此”误写成当前功能
8. 正式 AC 是否依赖了【待确认】内容
